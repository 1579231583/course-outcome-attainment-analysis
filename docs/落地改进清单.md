# 课程目标达成度分析系统 — 真实落地痛点与逐步改善清单

> 📌 本文档记录系统从“可运行原型（Demo）”迈向“高校真实教学可实际落地使用”的全部痛点、工程改造方案与验收标准。
>
> **状态图例**：✅ 已解决　🟡 进行中　⏳ 待解决

## 一、P0 级：架构安全与数据一致性硬伤（上线前必须彻底消灭）

| 编号 | 痛点描述 | 改造方案 | 验收标准 | 状态 |
| :---: | :--- | :--- | :--- | :---: |
| **P0-1** | **后端全局单态串数据**：`calc_engine.py` 和 `api.py` 中的 `METHOD`/`MATRIX`/`PAPER_STRUCTURE`/`META`/`CURRENT_ROSTER` 均为进程级全局变量，多名教师并发操作会互相覆盖配置。 | 将 `calc_engine.py` 所有核心函数重构为**无状态纯函数（显式传参 `config`）**；每个接口按请求的 `course_id` 从数据库读取配置独立计算，彻底移除全局状态依赖。 | 两个不同浏览器分别以教师 A/B 登录，同时操作高数与数据结构两门课，计算、模板下载与导出互不干扰。 | ✅ |
| **P0-2** | **后端接口无鉴权与数据隔离**：前端虽有登录，但后端 `/api/courses`、`/api/reports`、`/api/admin/*` 未校验 Token，也未按 `user_id` 隔离，普通教师可越权访问/删除他人数据及管理员接口。 | 在 `api.py` 增加 FastAPI `Depends` 鉴权依赖（`get_current_user` / `require_admin`）；前端请求头自动携带 `Authorization: Bearer <token>`；私有课程与历史报告严格按 `user_id` 隔离，管理员接口校验 `role == 'admin'`。 | 未登录请求返回 `401`；普通教师访问 `/api/admin/*` 返回 `403`；教师 A 看不到教师 B 的私有课程和班级报告。 | ✅ |
| **P0-3** | **公共课程模板会被普通教师误改**：教师选用管理员发布的公共模板后点击保存，会直接覆盖原公共模板。 | 实现 **Copy-on-Write（只读公共模板 + 选用即克隆私有副本）**：仅管理员可编辑公共模板；教师选用公共模板时自动克隆一份归属自己的私有课程配置副本。 | 教师选用《高等数学A(II)》公共模板并修改平时占比后保存，公共模板库中的原版规则保持不变。 | ✅ |
| **P0-4** | **前端步骤切换与后端配置不同步**：教师在第 1~3 步改完参数后，若直接点击顶部步骤条跳到第 5 步传成绩，未触发保存导致后端仍用旧配置解析。 | 切入第 5 步前自动触发配置校验与保存并更新当前 `course_id`，杜绝拿旧配置解析与计算。 | 第 2 步改完占比后直接点击顶部「5 传成绩」，系统自动校验并保存最新配置，解析和模板均生效最新规则。 | ✅ |

## 二、P1 级：高校真实教学场景业务刚需（解决老师“用不起来”的卡点）

| 编号 | 痛点描述 | 改造方案 | 验收标准 | 状态 |
| :---: | :--- | :--- | :--- | :---: |
| **P1-1** | **教务 Excel 格式兼容性不足**：正方/青果等教务系统常导出旧版 `.xls` 或 `.csv`，或工作簿含多个 Sheet（如 Sheet1 为说明、Sheet2 为成绩），当前只读 `.xlsx` 的首个 Sheet。 | 后端扩展支持 `.csv`、`.xls`（引入轻量库或转换）及多 Sheet 列表返回；若首 Sheet 未找到“学号/姓名”，自动扫描其余 Sheet 或允许前端下拉切换 Sheet。 | 上传多 Sheet 工作簿和 `.csv` 成绩表均能准确识别表头并解析。 | ⏳ |
| **P1-2** | **缺考 / 缓考 / 休学 / 五级制文字无法识别**：真实教务表常出现 `缓考`、`缺考`、`旷考`、`免修`、`优/良/中/及格/不及格`，当前直接当非法字符标红。 | 在解析器中增加**特殊状态识别器**：自动识别 `缓考/休学/退选`（建议一键剔除，不计入样本分母）、`缺考/旷考/违纪`（建议一键按 0 分计入），并提供五级制自动换算选项（95/85/75/65/50）。 | 上传含“缓考”“缺考”字样的真实成绩表，前端给出分类提示并支持一键批量处理。 | ⏳ |
| **P1-3** | **不支持“无期末笔试”的考查课 / 实验课**：当前强校验“试卷总分必须 == 100”，导致平时 100% 或纯实验/课程设计类课程无法使用。 | 当 `期末占比 == 0` 时，自动豁免试卷结构校验，向导自动跳过「4 配试卷」，第 5 步只需上传平时成绩表即可完成计算与导出。 | 配置一门平时 100%（实验 60% + 报告 40%）、期末 0% 的课程，可完整跑通并导出报表。 | ⏳ |
| **P1-4** | **OBE 认证核心要素缺失（毕业要求指标点 & 目标描述）**：前端尚无入口维护每个课程目标对应的「毕业要求指标点（如 1.2、2.1）」与目标详细描述。 | 在第 3 步目标配置中增加“目标描述”与“支撑毕业要求指标点”字段，随课程持久化并在终表与导出报告中完整呈现。 | 配置目标描述与指标点后，导出报表和报告预览均正确展示。 | ⏳ |
| **P1-5** | **大班成绩表性能与实用操作不足**：120 人 × 25 题同屏渲染 3000 个输入框易卡顿；缺少单学生实时总分/个人达成度预览及批量纠错工具。 | 成绩表格增加分页/虚拟滚动、单行实时展示该生总分与个人达成度、支持“一键删除所有缓考行 / 一键缺考补 0”及“导出纠错后原始成绩表备份”。 | 150 人 × 25 题成绩表切换流畅无卡顿，支持一键批量处理异常行。 | ⏳ |

## 三、P2 级：高价值交付物与生产级部署（从“能用”到“好用、能交差”）

| 编号 | 痛点描述 | 改造方案 | 验收标准 | 状态 |
| :---: | :--- | :--- | :--- | :---: |
| **P2-1** | **缺少一键导出 Word 版《课程目标达成情况评价报告.docx》**：高校认证归档除 Excel 计算表外，还需提交含文字、图表、持续改进措施和签字栏的正式 Word 报告。 | 后端引入 `python-docx` + 图表图片生成，一键导出排版规范的《课程目标达成情况评价报告.docx》（含封面/基本信息、毕业要求支撑表、评价终表、达成度柱状图、4 维诊断与持续改进措施、签字栏）。 | 点击「导出 Word 评价报告」即可下载可直接打印签字归档的 `.docx` 文档。 | ⏳ |
| **P2-2** | **数据库与容器化生产部署**：目前使用原生 `sqlite3`，需支持正式环境无缝切换 MySQL 及一键 Docker 部署。 | 将 `db.py` 升级为 **SQLAlchemy ORM**（通过环境变量 `DATABASE_URL` 默认 SQLite、一键切换 MySQL），并补齐 `Dockerfile`、`docker-compose.yml` 与部署文档。 | 本地免配置默认 SQLite 运行正常；配置 MySQL 连接串后表自动初始化且全接口通过。 | ⏳ |
| **P2-3** | **接入真实大模型激活 OBE 诊断 Agent（预留 RAG）**：当前诊断草稿为确定性规则模板，尚未接入真实 LLM Tool-Calling 与多轮问答。 | 后端支持配置 OpenAI 兼容 API Key（DeepSeek / 通义千问等），将 `diagnostics.py` 4 个下钻函数注册为 Agent Tools，前端报告页增加侧边栏多轮追问；远期再讨论扩展 RAG 教学大纲知识库。 | 配置 API Key 后，Agent 能自主调用工具查数并生成深度定制的持续改进报告。 | ⏳ |

## 四、推荐执行顺序

严格按 **小步快跑、每步自测、实时同步文档** 的节奏推进：
1. **第一轮（P0-1 + P0-2 + P0-3 + P0-4）**：先把并发串数据、Token 鉴权隔离、公共模板防误改和配置同步彻底修好，打牢地基；
2. **第二轮（P1-1 ~ P1-5）**：逐项攻克真实教务表格兼容、缺考缓考识别、无期末考查课支持与大班表格体验；
3. **第三轮（P2-1 ~ P2-3）**：交付 Word 评价报告导出、SQLAlchemy MySQL/Docker 生产化与真实大模型 OBE Agent。
