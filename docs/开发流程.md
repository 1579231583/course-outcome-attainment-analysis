## 一、需求分析（✅ 已完成）

### 1.1 核心业务场景

高校教师每学期需要完成"课程目标达成度"的统计与上报（工程教育认证/OBE 核心材料）。现状是靠 Excel 手工计算，繁琐且容易出错。本系统将全流程数字化。

### 1.2 达成度算法（已用真实数据验证）

五步计算流程，详见 [达成度计算流程.md](./达成度计算流程.md)。

关键公式：
$$产出权重_{ij} = 考核环节权重_j \times \frac{原始对应比例_{ij}}{\sum_i 原始对应比例_{ij}}$$
$$课程目标达成度_i = \frac{\text{全班实得均分}_i}{\text{理论满分}_i}$$

> ✅ 已用 44 人真实班级数据完整验证：目标 1 达成度 **62.9%**（理论满分 64.40），目标 2 达成度 **77.0%**（理论满分 35.60）。
> ✅ 单学生（俞高敏）手工推演与引擎输出逐位一致：目标 1 71.5% / 目标 2 82.6%。

### 1.3 教师操作流程

```
①网页配置课程规则（只做一次，可复用）          ✅ 已实现
        ↓
②配置试卷结构（大题 → 小题）                    ✅ 已实现（结构模板导入待做）
        ↓
③系统生成定制成绩录入模板（.xlsx）              ✅ 已实现
        ↓
④教师填好平时及期末小题分数后上传 Excel          ✅ 已实现
        ↓
⑤列映射确认抽屉 → 超分标红 → 就地双击纠错        ⏳ 未实现（当前直接报错提示）
        ↓
⑥一键触发计算 → 秒级出结果                      ✅ 已实现
        ↓
⑦网页查看：达成度卡片 + 评价终表 + 柱状图        🟡 仅达成度表格
        ↓
⑧一键导出官方 Excel 报表                        ⏳ 未实现
```

### 1.4 数据录入方式分工

| 录入方式 | 适用内容 | 理由 |
|---------|---------|------|
| **网页端交互表单** | 课程基本信息、考核环节及占比（成绩评定方法）、课程目标与环节对应关系矩阵、试卷结构 | 参数少，配置直观 |
| **Excel 批量上传** | 平时成绩明细（学号、姓名、各环节得分）、期末各小题得分 | 数据量大，教师最习惯 Excel 操作 |
| **已确定** | 期末试卷结构采用“大题分组 + 小题明细”，每道小题只对应一个课程目标；结构在系统配置，成绩表只填分 | 实现结构模板、成绩模板和校验 |

### 1.5 架构决策摘要

| 决策点 | 结论 | 理由 |
|-------|------|------|
| 开发顺序 | **先跑通计算内核 + Demo，再做工程化** | 尽早验证算法与数据格式，避免在错误前提上搭架构 |
| 数据库选型 | **MySQL**（规划中） | 生产级关系型数据库，支撑用户系统 |
| 数据库存储范围 | 仅存用户账号 + 报告摘要 | 海量小题成绩不入库，内存算完即可 |
| 计算引擎 | 当前 openpyxl 纯 Python，后续视需要引入 pandas | 44 人数据毫秒级完成，暂不需要 pandas |
| 配置存储 | 当前进程内存（重启丢失） | Demo 阶段简化，后续落库 |
| 班级单元 | 单班级核算 | 不做跨班合并，逻辑清晰 |
| 学生名单 | 教师自行复制粘贴 | 不维护学籍库，系统保持轻量 |
| 试卷结构 | 系统配置 + 生成录入模板（B 方案） | 教师只填分，杜绝表头错位 |
| AI 扩展 | 预留接口，不影响当前开发 | 后续版本再接入 |

### 1.6 计算结果呈现设计

**网页端三层展示**（由上至下）：
1. **指标卡片**：大字显示各目标达成度%，绿色=达标，黄色=未达标 ⏳
2. **评价终表预览**：满分行 + 实得均分行 + 达成度，所见即所得 ⏳
3. **柱状对比图**：带合格基准红虚线，可右键复制图片 ⏳

**导出按钮（两个）**：⏳
- 《评价汇总表.xlsx》→ 供教务存档 / 工程认证核查
- 《全班得分明细表.xlsx》→ 逐人逐题数据，供备查

## 三、可运行 Demo（✅ 已完成）

### 3.1 交付物

| 文件 | 说明 |
|------|------|
| `backend/api.py` | FastAPI：配置读写、模板下载、上传计算、静态托管 |
| `frontend/index.html` | 5 步式单页界面 |
| `frontend/app.js` | 配置渲染、矩阵编辑、试卷结构编辑、结果展示 |
| `frontend/style.css` | 样式 |

### 3.2 启动方式

```powershell
cd backend
.\venv\Scripts\Activate.ps1
python -m uvicorn api:app --reload --port 8000
# 浏览器打开 http://127.0.0.1:8000
```

### 3.3 已知限制

- 配置存内存，重启恢复默认。
- 上传出错时只返回文字报错，无列映射确认与就地纠错。
- 无导出、无图表、无用户体系。

> A 阶段实现要点：前端 `calcOutputWeights()` 复刻后端 `step2_output_weights()` 的列归一化逻辑，已用示例配置交叉验证（5.33/10.67、6.40/9.60、2.67/5.33、50.00/10.00，理论满分 64.40/35.60）。修改矩阵任一格、平时环节占比或平时/期末总占比，预览即时刷新。
